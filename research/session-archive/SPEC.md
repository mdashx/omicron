# Pi Session Archive Feature

## Intent

Add a startup-loaded session archive feature to Pi so every chat session is captured as append-only JSONL in a dedicated archive repository.

This must be enforced by runtime wiring, not by prompting the model to remember to log.

---

## 1. `SessionArchiveConfig`

### Prose Spec

`SessionArchiveConfig` defines whether archiving is enabled, where Pi writes the archive, which event types are captured, and how the archive behaves on failure.

Pi should load this before the agent loop starts. If archiving is required and the config is missing or invalid, startup should fail.

### Z Spec

```text
SessionArchiveConfig
  enabled: 𝔹
  repoPath: seq CHAR
  fileLayout: seq CHAR
  outputFormat: seq CHAR
  captureEvents: ℙ seq CHAR
  redactMode: seq CHAR
  failClosed: 𝔹
where
  enabled = true
  repoPath ≠ ⟨⟩
  fileLayout ≠ ⟨⟩
  outputFormat = ⟨"jsonl"⟩
  failClosed = true
```

### Data examples

```json
{
  "enabled": true,
  "repoPath": "/home/easter/session-archive-repo",
  "fileLayout": "yyyy/mm/dd/sessionId.jsonl",
  "outputFormat": "jsonl",
  "captureEvents": ["session_start", "message", "tool_call", "tool_result", "session_end", "error"],
  "redactMode": "minimal",
  "failClosed": true
}
```

### Implementation suggestions / specifics

- Load config in Pi startup, before the model session begins.
- Keep the archive config outside the prompt path.
- Use a fail-closed policy: if archiving is enabled, no archive means no session.
- Keep `jsonl` as the first and only archive format.
- Treat `repoPath` as a separate session archive repository, not the Pi code repo.

## 2. `PiSessionEnvelope`

### Prose Spec

`PiSessionEnvelope` identifies one Pi session and carries the metadata that applies to every archive event in that session.

The session ID must be generated by Pi at runtime, not by the model.

### Z Spec

```text
PiSessionEnvelope
  sessionId: seq CHAR
  startedAt: seq CHAR
  source: seq CHAR
  host: seq CHAR
  runtimeVersion: seq CHAR
  packageVersion: seq CHAR
  mode: seq CHAR
  cwd: seq CHAR
where
  sessionId ≠ ⟨⟩
  startedAt ≠ ⟨⟩
  source ≠ ⟨⟩
```

### Data examples

```json
{
  "sessionId": "2026-06-05T19:45:12Z_8f3a",
  "startedAt": "2026-06-05T19:45:12Z",
  "source": "pi-coding-agent",
  "host": "easter-laptop",
  "runtimeVersion": "2026.6.5",
  "packageVersion": "0.1.0",
  "mode": "interactive",
  "cwd": "/home/easter/omicron"
}
```

### Implementation suggestions / specifics

- Generate the session ID at startup using timestamp + short random suffix.
- Capture runtime metadata from Pi itself, not from the model.
- Store the envelope in the agent runtime state.
- Emit a `session_start` event immediately after the envelope is created.
- Keep the envelope immutable for the rest of the session.

## 3. `PiArchiveEvent`

### Prose Spec

`PiArchiveEvent` is one JSONL record. It captures a single runtime event: user input, assistant output, tool call, tool result, system lifecycle marker, or error.

### Z Spec

```text
EVENTTYPE ::= session_start | message | tool_call | tool_result | session_end | error
ROLE ::= user | assistant | tool | system

PiArchiveEvent
  sessionId: seq CHAR
  eventId: seq CHAR
  timestamp: seq CHAR
  role: ROLE
  eventType: EVENTTYPE
  content: seq CHAR
  metadata: seq CHAR
where
  sessionId ≠ ⟨⟩
  eventId ≠ ⟨⟩
  timestamp ≠ ⟨⟩
  content ≠ ⟨⟩ ∨ eventType = session_start
```

### Data examples

```json
{
  "sessionId": "2026-06-05T19:45:12Z_8f3a",
  "eventId": "evt_0001",
  "timestamp": "2026-06-05T19:45:15Z",
  "role": "user",
  "eventType": "message",
  "content": "write a session archive harness",
  "metadata": "{\"channel\":\"interactive\"}"
}
```

### Implementation suggestions / specifics

- Append one JSON object per line.
- Validate each record before write.
- Keep `metadata` compact and machine-readable.
- Include `session_end` on clean shutdown.
- Preserve content unless redaction policy requires otherwise.

## 4. `PiArchiveWriter`

### Prose Spec

`PiArchiveWriter` is the persistence layer that writes Pi archive events to disk.

It must be append-only and flush often enough that a crash does not destroy the session record.

### Z Spec

```text
PiArchiveWriter
  config: SessionArchiveConfig
  envelope: PiSessionEnvelope
  filePath: seq CHAR
  appendOnly: 𝔹
  flushed: 𝔹
where
  appendOnly = true
```

### Data examples

```json
{
  "filePath": "/home/easter/session-archive-repo/2026/06/05/2026-06-05T19-45-12Z_8f3a.jsonl",
  "appendOnly": true,
  "flushed": true
}
```

### Implementation suggestions / specifics

- Create one file per session.
- Resolve the file path from `fileLayout`.
- Open the file in append mode only.
- Flush after each event or very small batch.
- Never rewrite old records in place.
- Keep archive storage separate from the Pi source tree.

---

## 5. `PiArchiveEnforcement`

### Prose Spec

`PiArchiveEnforcement` describes the runtime guarantees that make archiving mandatory and independent of LLM behavior.

Pi should wire the archive plugin into startup, event hooks, and shutdown. The model should never be the source of truth for whether a session is recorded.

### Z Spec

```text
PiArchiveEnforcement
  pluginLoaded: 𝔹
  hooksInstalled: 𝔹
  schemaValidated: 𝔹
  startupBlockedIfMissing: 𝔹
  llmInPath: 𝔹
where
  pluginLoaded = true
  hooksInstalled = true
  schemaValidated = true
  startupBlockedIfMissing = true
  llmInPath = false
```

### Data examples

```json
{
  "pluginLoaded": true,
  "hooksInstalled": true,
  "schemaValidated": true,
  "startupBlockedIfMissing": true,
  "llmInPath": false
}
```

### Implementation suggestions / specifics

- Load the archive plugin before the agent loop starts.
- Register hooks for input, tool calls, tool results, output, and shutdown.
- Validate records before they reach the writer.
- Fail startup if archiving is enabled but unavailable.
- Keep all archive decisions in Pi runtime code, not in prompts or model output.

---

## Suggested first milestone

Pi can start a session, create a timestamped session archive file, log `session_start`, append every input and tool/output event as JSONL, and close with `session_end` without the model deciding anything about archiving.
